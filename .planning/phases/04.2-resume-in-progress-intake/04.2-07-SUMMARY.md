**Resolved the one genuine source contradiction in the phase.** The research recorded official WebKit
copy implying partitioned-but-working against a non-authoritative blog claiming `SecurityError` on
write in cross-origin iframes. Measured: Safari does **not** throw.

**A first attempt measured the wrong thing and was discarded** — it loaded
`alle-drops-quiz-app.fly.dev/quiz-embed` directly as a top-level page, which is *first-party*
storage, a context Safari has never restricted. Corrected by framing the app from a local top-level
page and selecting the `quiz-embed` frame in Web Inspector (`isTop: false` confirmed). Recorded
because the probe output looks identical in both contexts.

**Caveat carried forward:** the survival result contradicts webkit.org's published "ephemeral,
cleared between application launches" policy. Measurement beats documentation for this version, but
it is one version on one platform. A future WebKit release could reinstate ephemeral clearing, and
because D-01 degrades silently that would never surface as an error — it would just quietly stop
working.

**Highest-value remaining gap: iOS Safari.** Not run. Every iOS browser is WebKit, iOS users quit
apps far more aggressively than desktop users, and `WKWebView`'s ITP day-counter is documented to
reset on app relaunch. **macOS passing does not imply iOS passes.**

**No escalation.** D-03's trigger requires storage unusable in a *majority* of rows that matter.
Both measured engines pass cleanly. D-02's deferred App Proxy alternative stays deferred.

## The defect Andrew found — and what it says about the checks

**Symptom:** the restart UI rendered far larger than the approved UI-SPEC's "low-emphasis utility
control" intent.

**Root cause, and it is not Phase 4.2.** Every font-size in `quiz.module.css` is written as
`var(--font-body-size, X)`, but `app/routes/quiz-embed.tsx:40` **defines** `--font-body-size: 1.6rem`
on `:root`. A CSS fallback applies only when the variable is undefined. Every fallback in the file is
therefore dead code, and all 102 declarations collapse to 1.6rem:

| Intended | Count | Actually renders |
|---|---|---|
| 1.4rem | 50 | 1.6rem |
| 1.6rem | 28 | 1.6rem |
| **1.2rem** (Caption role) | **17** | **1.6rem** |
| 1.1 / 1.3 / 1.5 / 1.8rem | 7 | 1.6rem |

The quiz renders **one** font size, not the three the UI-SPEC declares, and every responsive
font-size media query in the file is inert.

**Fixed here (`507b241`):** only Phase 4.2's three declarations, using explicit rem. Those are a
deviation from *this phase's* approved contract. Bundle rebuilt in the same commit, determinism
proven by identical SHA-256 across two builds, 04.1's `QUIZ_PARTS` reorder re-verified present at
index 0 in the rebuilt artifact.

**Deliberately not fixed:** the other 99 declarations. Pre-existing, spanning every quiz surface from
phases 1–4. Re-sizing the whole questionnaire needs its own browser pass, not a drive-by inside a
phase about to ship. Logged for Andrew's scoping decision.

**Why every automated gate missed it.** The UI-SPEC *declared* three type sizes. `gsd-ui-checker`
verified the spec declared three sizes. 677 tests passed. None of those inspect what a browser
paints. A human glanced at the screen and saw it immediately — which is the entire justification for
this plan existing, now demonstrated rather than asserted. Seven UAT defects on this project have now
been caught by a human and missed by a green suite.
