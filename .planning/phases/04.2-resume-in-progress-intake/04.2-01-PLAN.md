Create `app/lib/quiz/draft-store.ts` as a pure module: no React import, named exports only, nothing
throws outward to a caller. Implement exactly the interface listed in this plan's `<interfaces>`
block.

`DRAFT_STORAGE_KEY = "alledrops_quiz_draft_v1"`. `DRAFT_EXPIRY_MS = 24 * 60 * 60 * 1000` (D-05).

`isStorageAvailable()` — a real write-read-remove round-trip canary against
`window.localStorage` using the probe key `__alledrops_storage_probe__`, returning true only when
`getItem` returns the exact value just written, all wrapped in try/catch returning false. A
`typeof window.localStorage !== "undefined"` check is explicitly forbidden. Write a doc comment
recording WHY: measured on Chrome desktop 2026-08-10 (see 04.2-RESEARCH.md § "Chrome desktop
measurement"), Chrome does not throw on partitioned/blocked third-party-iframe storage, so the
round-trip equality is the only thing that catches the silent-no-op failure shape. Also guard
`typeof window === "undefined"` (SSR) by returning false.

`schemaFingerprintFor(items)` — a deterministic string derived from the live question set:
`items.map(item => item.kind + ":" + item.id + ":" + (isQuestion(item) ? item.type : "")).join("|")`.
Do not hash it; the value never leaves the browser and a readable string is easier to debug without
logging anything. `currentSchemaFingerprint()` returns `schemaFingerprintFor(ALL_ITEMS)`. Doc comment
must state this is self-maintaining by design — it changes automatically when a question is added,
removed, renamed, or retyped, which is the failure class Phase 4.1's `QUIZ_PARTS` reorder would
otherwise reopen, and this project has a documented history of hand-maintained version constants not
getting bumped.

`stripFileTokens(answers)` — returns a new `QuizAnswers` with every key removed whose corresponding
item in `ALL_ITEMS` is a question with `type === "file_multi"`. Type-driven off `item.type`, never a
hardcoded `"testing_files"` literal, matching SCH-02's no-question-ID-literals discipline. This is
D-11's mechanism.

`writeDraft(draft, fingerprint = currentSchemaFingerprint())` — no-op (silently, no throw, no log)
when `isStorageAvailable()` is false. Otherwise serialize `{ ...draft, answers: stripFileTokens(draft.answers), schemaFingerprint: fingerprint, savedAt: Date.now() }`
with `JSON.stringify` and `setItem`. Wrap the whole body in try/catch that swallows (a quota
exception on a shared device must never surface to the patient — D-01). Never persist `score`,
`scoreBracket`, `startTime`, `consentChecked`, `patientInfoShowErrors`, `submissionError`, or
`showTestMode`; the `QuizDraftInput` type is what enforces this, so do not widen it.

`readDraft(fingerprint = currentSchemaFingerprint())` — returns `QuizDraft | null`, collapsing EVERY
failure reason to the same `null`: storage unavailable, missing key, `JSON.parse` throw, non-object
parse result, `schemaFingerprint` mismatch, non-numeric or expired `savedAt`, missing/empty
`answers`. Write the doc comment in `visibleAnswers`'s style explaining that the collapse is a
requirement, not a convenience: 04.2-UI-SPEC.md § "Absent State" requires the D-01 path and the
"no draft" path to be indistinguishable, ideally the same branch. On fingerprint mismatch and on
expiry, call `clearDraft()` before returning null (active cleanup, so a permanently-stale draft does
not linger). Before returning a valid draft, apply `stripFileTokens` to its `answers` a second time —
defence in depth against a hand-edited draft, so a tampered `testing_files` value can never re-enter
React state (D-11).

`clearDraft()` — `removeItem(DRAFT_STORAGE_KEY)` inside try/catch, no-op when storage is
unavailable, never throws.

CLAUDE.md compliance, non-negotiable: this file must contain zero occurrences of the string
`console.` anywhere, including inside catch blocks. The draft object holds name, dob, email, phone,
and answers — logging it, or logging a caught error that might carry it, is a PHI leak. Catch blocks
swallow with an empty body plus an explanatory comment.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| React state → `window.localStorage` | PHI leaves volatile memory and lands in plaintext on the patient's device for up to 24h (D-04, accepted) |
| `window.localStorage` → React state, across deploys | A stored draft is untrusted input: it may have been written by a prior deploy's question set, or hand-edited in DevTools |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4.2-01 | Information Disclosure | The draft at rest in `localStorage` | accept | D-04 is an informed decision with the shared-device trade-off recorded. `localStorage` has no encryption primitive and a client-held key buys nothing against a same-profile reader (04.2-RESEARCH.md § Security Domain, V6 named limitation). Mitigations are lifecycle, not cryptographic: `DRAFT_EXPIRY_MS` 24h with active `removeItem` on read, the D-07 write gate, D-06's zero-identity offer, and D-08's clear controls |
| T-4.2-02 | Information Disclosure | Debug logging inside `draft-store.ts` | mitigate | Zero `console.` occurrences enforced by a source-text assertion in `draft-store.test.ts`; catch blocks swallow with a comment rather than logging the caught error |
| T-4.2-03 | Tampering | A stale or hand-edited draft restored into the current question set | mitigate | `schemaFingerprintFor(ALL_ITEMS)` validated on every `readDraft`; mismatch discards AND removes the key. Fingerprint is derived from `kind:id:type` so it changes automatically when `questions.ts` changes |
| T-4.2-04 | Tampering | A dead GCS staging token carried from a draft into a clinical submission | mitigate | `stripFileTokens` applied on BOTH `writeDraft` and `readDraft`, keyed off `item.type === "file_multi"`, proven at the serialized-string level with `split(needle).length - 1` |
| T-4.2-SC | Tampering | npm/pip/cargo installs | mitigate | This phase installs zero packages (04.2-RESEARCH.md § Standard Stack, § Don't Hand-Roll). No Package Legitimacy Audit table is required because there are no install tasks. Phase gate asserts `git diff -- package.json package-lock.json` is empty |
</threat_model>
