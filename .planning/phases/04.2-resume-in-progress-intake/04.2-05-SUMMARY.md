## Accomplishments

- A single `useEffect` in `QuizContainer.tsx` gates on `typeof window`, then on `step` (only `quiz_parts`/`consent` ever schedule a write), then on `Object.keys(answers).length` — before scheduling a 500ms trailing `setTimeout` that calls `writeDraft`. All three gates run before any timer is created, so an untouched page load, the state gate, and patient-info typing (including all four identity PHI fields) leave zero trace, proven by direct `window.localStorage.length === 0` assertions after the debounce window elapses.
- `clearDraft()` added inside `handleConsentSubmit`'s `try` block, immediately after `await submitPayload()` resolves and before `setStep("results")` — verified to appear zero times in the `catch` branch, so a transient network error never costs the patient their answers (D-08).
- `QuizPartRendererProps` gains an optional `resumedSession` prop (default `false`); the existing `entries.length === 0` dropzone branch now selects between the D-09/D-11 resumed copy and the unchanged default, reusing `styles.fileUpload__empty` with zero new CSS. `QuizContainer` threads its existing `resumedSession` state down to the renderer. The `showRequiredEmptyError` block and `requiredEmptyMessage()` are byte-for-byte untouched (confirmed via `git diff`).
- `StartOverControl` renders directly below the progress bar and above `quizContainer__questions`, guarded by `step === "quiz_parts" || step === "consent"` — never inside the bottom nav row. `handleStartOver` clears the draft and resets all twelve pieces of in-memory quiz state (`answers`, `patientState`, `patientInfo`, `patientInfoShowErrors`, `currentPartIndex`, `score`, `scoreBracket`, `symptomProfileId`, `consentChecked`, `submissionError`, `resumedSession`, `showRestorationNotice`), landing on `state_gate`. `startTime` is deliberately not reset (D-10's named exclusion).
- `tests/quiz-resume-write-gate.test.ts` (9 tests): untouched load, state gate, patient-info typing, zero-answers-on-quiz_parts, first-real-answer, debounce (10 rapid keystrokes → strictly fewer than 10 `DRAFT_STORAGE_KEY` writes), Test Mode exclusion, clear-on-success, keep-on-failure.
- `tests/quiz-resume-no-file-token.test.ts` (5 tests): a real file upload's staging token and `testing_files` both occur **zero** times in the raw serialized draft (`source.split(needle).length - 1`), while `testing_year` occurs at least once (non-vacuity control); the resumed/non-resumed dropzone copy split; the 04.1 upload wall surviving resume (disabled Next, required-but-empty error still fires on blur); a re-upload re-opening the wall.
- `tests/quiz-resume-start-over-dom.test.ts` (10 tests): the control's visibility range (absent on `state_gate`/`patient_info`/`resume_offer`, present on `quiz_parts`/`consent`); the confirm panel protecting the draft on both the first tap and the "Keep my progress" dismiss; destruction on "Yes, start over"; the write effect's step gate proving no immediate rewrite even past the debounce window; both Start-over triggers (in-flow and resume-offer) landing on the identical state-gate screen.
- RED proof performed and recorded (see Issues Encountered): the `Object.keys(answers).length === 0` gate was temporarily removed, the "zero answers on quiz_parts" test observably failed with the expected message, then the mutation was reverted (confirmed via `git diff` showing the file returned to its prior committed state) and the full write-gate suite passed again.
