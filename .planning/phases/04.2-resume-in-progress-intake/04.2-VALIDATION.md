## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 3.2.4 |
| **Config file** | `vitest.config.ts` — `environment: "node"` by default; DOM tests opt in per-file via `// @vitest-environment jsdom` (convention from Phase 3's `tests/quiz-part-renderer-dom.test.ts`) |
| **Quick run command** | `npx vitest run tests/<file>.test.ts` |
| **Full suite command** | `npm test` (`vitest run`) |
| **Baseline at phase start** | **602 tests / 39 files, all passing** — measured 2026-08-10 on `phase-4.2-resume-in-progress-intake` |
| **Estimated runtime** | full suite ~2.1s |

⚠️ **`.test.ts`, never `.tsx`** — vitest's `include` glob does not match `.tsx`. DOM tests use
`React.createElement`, not JSX. This cost time in Phase 3; do not rediscover it.

⚠️ **Never `grep -c` to count occurrences in the built bundle.** `grep -c` counts *lines*, and the
minified bundle is one line. Use `SOURCE.split(needle).length - 1`. This project has burned time on
this twice.

## Sampling Rate

- **After every task commit:** the specific test file(s) that task touched — `npx vitest run <file>`
- **After every plan wave:** `npm test` (full suite) + `npm run typecheck`
- **Before `/gsd:verify-work`:** full suite green **AND** the human browser pass below
- **Max feedback latency:** ~2.1 seconds (full suite)

Additional per-wave gate unique to this repo: **any wave touching `app/components/quiz/` or
`app/lib/quiz/` must rebuild `public/quiz-bundle.js`** with `npm run build:theme` **in the same
commit**. `npm run build` does not touch it. `tests/quiz-bundle-freshness.test.ts` guards this; it
exists because the omission shipped an invisible phase in session 32.

**Phase-4.2-specific carry-forward:** this branch is forked from `phase-4.1-testing-first-quiz-order`,
whose reordered `QUIZ_PARTS` is baked into the committed bundle. Any rebuild in this phase must keep
04.1's part-order guard green — a rebuild from a stale base would silently revert the reorder while
every test still passes.

**D-10's named exclusions** (fields allowed to differ between a one-sitting run and a resumed run —
the test must exclude these explicitly and by name, not by a loose matcher):
`completion_time`, `quiz_date`, and `symptom_profile_id` (research confirmed
`generateSymptomProfileId()` is `` `AOD_${Date.now()}` ``, so it is time-derived like the other two).
Everything else must be deep-equal, and `quiz_score` / `score_bracket` must be strictly equal.

**Why the D-01 test must cover two failure modes, not one.** Measured on Chrome desktop 2026-08-10
(`04.2-RESEARCH.md` §"Chrome desktop measurement"): Chrome's third-party-iframe storage **does not
throw**. A `try/catch`-only feature-detect would therefore report "storage available" on a browser
where it may not persist. The round-trip-equality canary is load-bearing, and the test suite must
prove the silent-no-op branch, not just the throwing branch.
