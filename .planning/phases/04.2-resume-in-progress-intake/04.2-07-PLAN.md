<interfaces>
<!-- The two surfaces this plan uses, and why they are different. -->

Surface 1 — functional pass:  npm run dev  ->  http://localhost:3000/quiz-embed
  This renders the quiz TOP-LEVEL. First-party storage. Correct for verifying flow, copy, focus, and
  the upload wall. NOT representative of the production storage condition.

Surface 2 — partitioned-storage pass: a local static page on a DIFFERENT origin embedding surface 1
  in an iframe, e.g. a one-file page served by `python3 -m http.server 8747` at
  http://127.0.0.1:8747/ containing <iframe src="http://localhost:3000/quiz-embed?test=0"></iframe>.
  `localhost` and `127.0.0.1` are distinct sites to the browser, so this reproduces the third-party
  frame condition the production Shopify embed creates.

Surface 3 — D-03 Safari harness: the already-deployed https://alle-drops-quiz-app.fly.dev/quiz-embed
  embedded in the same local static page. This measures Safari's storage policy against the real
  production ORIGIN and does not require this phase to be deployed first — the probe tests the
  browser, not the feature.

Freshness proof technique (04.1-05 precedent): fetch /quiz-bundle-js with a `?cb=<nanoseconds>` cache
buster and compare the served byte length to `wc -c public/quiz-bundle.js`. Verify on served bytes,
never on an exit code.
