## Pattern Assignments

### `app/lib/quiz/draft-store.ts` (utility, CRUD)

**No storage-specific analog exists in this codebase — confirmed by fresh grep above.** The closest
*structural* analog is `app/lib/quiz/schema.ts`'s `visibleAnswers` (a pure, named-export, no-React,
"fold every reason into one return value" function) and `app/lib/quiz/scoring.ts` (a pure module with
zero side effects, one clear input/output contract per function, plain JSDoc above each export).

**Module shape convention to copy** (`app/lib/quiz/schema.ts:1-10` header style, `scoring.ts:1-2`
imports):
```typescript
// scoring.ts's import block — named type-only import from ./types, no React, no relative-parent
// escapes beyond the lib/quiz directory itself.
import { type QuizAnswers, type QuizQuestion } from "./types";
```
`draft-store.ts` should mirror this: `import { type QuizAnswers } from "./types";` plus a type-only
import of `ALL_ITEMS`/`isQuestion` from `./questions` and `./schema` for the fingerprint helper
(Pattern 2 below) — no React import anywhere in this file (RESEARCH.md's explicit constraint).

**Null-collapsing failure modes — copy this doc-comment discipline directly** from
`app/lib/quiz/schema.ts:150-189` (`visibleAnswers`'s own header, which explains *why* it fails open
one specific direction, not just what it does). `draft-store.ts`'s `readDraft()` needs the identical
treatment: one paragraph stating that storage-unavailable, missing-key, corrupt-JSON,
schema-mismatch, and expired all collapse to the same `null`, and why (UI-SPEC's explicit
requirement that D-01 and "no draft" are indistinguishable).

**Concrete shape already drafted in RESEARCH.md** (`04.2-RESEARCH.md` lines 287-321, 334-350) —
treat as the reference implementation, not merely illustrative, since it was produced by reading this
exact codebase's conventions:
```typescript
// app/lib/quiz/draft-store.ts — canary pattern (RESEARCH.md Pattern 1)
export function isStorageAvailable(): boolean {
  try {
    const probe = "__alledrops_storage_probe__";
    window.localStorage.setItem(probe, "1");
    const ok = window.localStorage.getItem(probe) === "1";
    window.localStorage.removeItem(probe);
    return ok; // catches BOTH throw-on-access AND silent-no-op engines
  } catch {
    return false;
  }
}
```
Real write-read-remove round-trip, never a `typeof` check — this is load-bearing per the Chrome
desktop measurement in RESEARCH.md (Chrome does not throw on a blocked/partitioned store; only the
round-trip-equality check catches it).

**Type-driven strip list (D-11), copy from `schema.ts`'s own blacklist discipline** — `visibleAnswers`
frames itself explicitly as "keep everything except what I specifically recognize," never a whitelist.
`stripFileTokens` in `draft-store.ts` must follow the identical discipline, keyed off `item.type ===
"file_multi"` (from `ALL_ITEMS`), never a hardcoded question-ID literal like `["testing_files"]`
(RESEARCH.md Pattern 2, `04.2-RESEARCH.md:334-350`).

## Shared Patterns

### Pure module discipline (`app/lib/quiz/*`)
**Source:** `app/lib/quiz/scoring.ts`, `app/lib/quiz/schema.ts`
**Apply to:** `draft-store.ts`, `payload.ts`
No React import, named exports only, every function documented with a JSDoc block explaining *why*
(not just what) when the function encodes a non-obvious decision (see `visibleAnswers`'s and
`toggleOption`'s doc comments as the house style). Both new files sit in `app/lib/quiz/` alongside
these exact analogs.

### DOM test harness (`.test.ts`, `// @vitest-environment jsdom`, `React.createElement`)
**Source:** `tests/quiz-part-renderer-dom.test.ts:1-50`, `tests/quiz-file-upload-dom.test.ts:1-92`
**Apply to:** `tests/quiz-resume-payload-parity.test.ts`, `tests/quiz-resume-write-gate.test.ts`,
`tests/quiz-resume-no-file-token.test.ts`

Every new DOM test in this phase MUST:
1. Start with `// @vitest-environment jsdom` as the literal first line of the file (before imports),
   exactly as both existing DOM test files do — `vitest.config.ts` defaults to `"node"`, this pragma
   is the only thing that makes `localStorage`/`document` real.
2. Use the `.test.ts` extension, never `.test.tsx` — `vitest.config.ts`'s `include` glob

   `quiz-file-upload-dom.test.ts:21` does) from `"@testing-library/react"`, plus `import React from
