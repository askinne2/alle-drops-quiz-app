Counting rule, non-negotiable — four agents on this project have already been burned by it:
  occurrences = SOURCE.split(needle).length - 1
  NEVER `grep -c`. The bundle is effectively one line, so `grep -c` returns 1 for any needle present
  anywhere and makes every `>= 1` gate pass vacuously.
  For shell-side measurement use:
    node -e "const s=require('fs').readFileSync('public/quiz-bundle.js','utf8');console.log(s.split(process.argv[1]).length-1)" '<needle>'

Marker admissibility rule (this file's own governing rule, see its plan-04-18 header note):
  A candidate marker MUST measure 0 against the PRE-rebuild committed bundle and >= 1 against the
  fresh rebuild. A candidate that already counts >= 1 before the change cannot prove staleness and
  MUST be replaced, not explained away. `file_multi` was rejected on exactly these grounds.

esbuild behaviour relied on: quoted string literals and CSS Modules class names survive minification
verbatim; local identifiers are mangled and must never be used as markers.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source tree → committed build artifact | The bundle is generated, committed, and served to the storefront. A stale artifact means the source is correct and the patient still sees the old page. This is the boundary the whole plan exists to police. |
| committed artifact → storefront browser | `quiz-bundle.js` is loaded cross-origin in the quiz iframe. It must contain no secret and no PHI. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-25 | Repudiation (silent no-op ship) | `public/quiz-bundle.js` freshness | mitigate | The session-28 incident on this very project. Mitigated by rebuilding in Task 1 and by eight-plus measured markers in Task 2 that go red if a future plan changes the quiz without rebuilding. |
| T-5-26 | Repudiation (vacuous marker) | New freshness markers | mitigate | A marker already present before the change proves nothing; `grep -c` on a one-line bundle makes any `>= 1` gate pass. Mitigated by the mandatory measured 0-before / ≥1-after table and by exclusive use of `split().length - 1`. |
