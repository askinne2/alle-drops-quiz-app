<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser file picker → upload endpoint | Client-side checks are courtesy only; the server is authoritative |
| local upload state → answers.testing_files | Writing a token for a file that did not succeed silently satisfies a clinical required gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-80 | Tampering | A token written for an uploading or failed file, satisfying the required gate falsely | mitigate | Tokens are written only at `status: "uploaded"`; Task 3 asserts the uploading and failed cases contribute zero tokens |
| T-4-81 | Elevation of Privilege | Client-side caps treated as the control | mitigate | The client pre-check exists only to shorten feedback; plan 04-13's `parseFormData` caps remain authoritative and are separately tested |
| T-4-82 | Information Disclosure | Filename rendered into a URL, a log, or telemetry | mitigate | The filename is held in component state and interpolated into copy only; the server never sends it back; no request path or query string carries it |
| T-4-83 | Denial of Service | A required upload trapping a patient with no way forward | mitigate | The info block's second paragraph is the explicit escape hatch to the `needs_testing` branch, and Task 1 forbids trimming it. Plan 04-19's human pass is the real control — no structural test can judge whether the copy reads as forgiving |
| T-4-84 | Information Disclosure | Orphaned staged objects from files hidden by a `testing_status` flip | accept with control | Hidden-answer retention means a file uploaded then hidden never reaches the backend as a linked token. The `pending/` OLM rule (plan 04-17) deletes it after `PENDING_OLM_AGE_DAYS`. Recorded here so it is a known consequence, not a surprise |
| T-4-85 | Spoofing | Error state signalled by colour alone | mitigate | Every error string is prefixed with `⚠` and carries `role="alert"`; each status icon has a visually-hidden text equivalent |
