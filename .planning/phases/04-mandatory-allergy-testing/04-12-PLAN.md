Build the three storage primitives the upload route composes: a GCS client module, a content
validator, and a HEIC converter. No route, no database, no UI — just the pieces, each independently
testable.

Two of these have real in-repo analogs and one does not. `gcs.ts` mirrors `app/lib/db.ts`'s
lazy-init, env-driven, throw-a-clear-config-error singleton. `upload-validation.ts` mirrors
`app/lib/quiz-validation.ts`'s pure, non-throwing, safe-default style. `heic.ts` has **no analog
anywhere in this codebase** — image-format conversion has never been done here — so
04-RESEARCH.md's `heic-convert` entry is its only source.

Purpose: TEST-04's security controls live here. Magic-byte sniffing is the mitigation for
MIME-spoofing; the size caps are the mitigation for memory exhaustion on a 1 GB VM.
Output: three modules plus unit tests using real device-shaped byte fixtures.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| patient-supplied filename → GCS object key | A filename is fully attacker-controlled and is used to build a storage path |
| patient-supplied bytes → allowlist decision | The declared MIME type and extension are advisory and spoofable |
| signed URL → anyone holding it | A signed URL is a bearer credential for a PHI file |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-50 | Tampering | MIME/extension spoofing to smuggle a disallowed file | mitigate | `sniffType` decides acceptance from bytes; Task 2 asserts an ASCII-text buffer named `results.pdf` returns `null`. The declared `Content-Type` is never consulted |
| T-4-51 | Elevation of Privilege | Path traversal / object-name injection via filename | mitigate | `sanitizeObjectName` strips separators, `..`, null bytes and control characters; Task 1 asserts every built key still starts with its configured prefix for adversarial inputs |
| T-4-52 | Information Disclosure | Signed URL leaking via logs, referrer, or browser history | mitigate | TTL fixed at `SIGNED_URL_TTL_SECONDS` (300); `responseDisposition: attachment` so it is never inline-rendered; routes in plan 04-14 add `Cache-Control: no-store` and keep the URL out of any log line |
| T-4-53 | Information Disclosure | Uploaded file rendered inline in a browser context | mitigate | `getSignedReadUrl` always sets an `attachment` disposition; enforced by the CLAUDE.md checklist bullet added in plan 04-01 |
| T-4-54 | Information Disclosure | Bucket or project hardcoded outside the BAA chain | mitigate | Both come from `process.env`; Task 1's acceptance criteria assert no bucket/project literal exists in the file |
| T-4-55 | Denial of Service | Memory exhaustion from oversized input on a 1 GB VM | mitigate | `MAX_FILE_BYTES` / `MAX_TOTAL_BYTES` / `MAX_FILES` exported here and enforced during streaming by plan 04-13, before full buffering; plan 04-17 bumps VM memory |
| T-4-56 | Denial of Service | HEIC decode CPU cost on a shared CPU | accept with control | Conversion is bounded by `MAX_FILE_BYTES` and by one file per request; the VM bump in plan 04-17 is the named mitigation and load behavior is observed during plan 04-19's pass |
| T-4-57 | Information Disclosure | `@google-cloud/storage` Node client telemetry (Assumption A3) | mitigate | Plan 04-13 runs a network capture during an upload and records every destination host; any host outside `*.googleapis.com` is a stop-and-report condition |

No packages installed in this plan (plan 04-10 owns the install).
</threat_model>
