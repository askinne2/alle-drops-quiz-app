<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client-supplied `fileId` → PHI file | Guessable or enumerable IDs must not be sufficient to reach a file |
| signed URL → anyone holding it | The URL is a bearer credential for a PHI object |
| admin session → every patient's files | Admin auth is not ownership; the audit log is the compensating control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-66 | Elevation of Privilege | IDOR across submissions on the patient route | mitigate | Ownership is re-proved in SQL via `getSubmissionFileForCustomer` (joins through `submissions`, constrains by `customer_id_shopify` OR `patient_email` AND `submission_id`); the test asserts the signed-URL mock has zero calls in the not-owned case |
| T-4-67 | Information Disclosure | Existence oracle distinguishing "not yours" from "not found" | mitigate | Both cases return byte-identical 404 bodies on both routes, asserted by test |
| T-4-68 | Information Disclosure | Signed URL captured in logs, referrer, or browser history | mitigate | 300-second TTL, `Cache-Control: no-store` on the carrying response, `Content-Disposition: attachment`, and a console spy asserting the URL never reaches a log line |
| T-4-69 | Repudiation | Admin file access not attributable | mitigate | `logSubmissionAccess({ action: 'file' })` on every admin file fetch, with the CHECK constraint widened in migration 004; asserted called exactly once |
| T-4-70 | Denial of Service | A slow or failing audit write blocking a clinical response | mitigate | The audit write is fire-and-forget with `.catch()`, never awaited; a rejecting write is asserted to still yield 200 |
| T-4-71 | Tampering | A write path appearing on the insert-only `submissions` table | mitigate | D-08 forbids it; the verify script fails the task if `reviewed_at`, a PATCH, or an `UPDATE submissions` appears in either admin file |
| T-4-72 | Information Disclosure | Filename in a URL path, query string, or referrer header | mitigate | Both routes take opaque IDs only; the filename travels solely in the signed URL's `responseDisposition`, generated server-side |
| T-4-73 | Denial of Service | Proxying file bytes through the 1 GB Fly VM | mitigate | Neither route streams bytes; both return a signed URL the browser fetches directly from GCS |

No packages installed in this plan (plan 04-10 owns the install).
</threat_model>
