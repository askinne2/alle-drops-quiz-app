<objective>
Fix the child half of the navigation contract and the medication label. Everything in this plan ships
through the Fly channel — the `no-store` `/quiz-embed` HTML and the 300-second-cached
`/quiz-bundle-js` artifact.

Purpose: `Location.assign` is a `[LegacyUnforgeable]` own property, so `quiz-embed.tsx:57-59`'s
reassignment fails **silently** in the sloppy-mode inline script (verified descriptor:
`{writable:false, configurable:false}`, no throw). That single mistake is the root cause of four of
the five broken exits. The fifth, the anchor, has a different bug with the same symptom: line 70
resolves `new URL(href, window.location.href)` where `window.location.href` is the **Fly** origin, so
the parent is handed `https://alle-drops-quiz-app.fly.dev/products/...` and navigates the storefront
off to the Fly domain. This corrects the earlier audit claim that the anchor path "works" — it does
not.

The message payload key changes from `url` to `path`. This is not cosmetic. `/quiz-bundle-js` carries
`max-age=300` with **no ETag and no Last-Modified**, so there is a real window in which an old bundle
talks to a new parent (or vice versa). Under the old key name that skew would pass an absolute URL to
a handler expecting a relative path; renaming makes the skew fail **closed**.

Output: no `location.assign` reassignment anywhere, five exits posting relative paths, two new config
keys, and a label that reads as designed while still being enforced.
</objective>
