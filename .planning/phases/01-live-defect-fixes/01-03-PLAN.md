Rewrite the parent side of the postMessage contract in the theme app block: add the missing

`symptom-quiz.liquid:59-67` validates neither `e.origin` nor the payload, and calls

`grep -c scrollToTop` on the live storefront HTML returns **0**. The correct handler exists at
`app/entry.theme.tsx:69-71` but that embed path is not installed, which is exactly why the defect
looked implemented for two months.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| **iframe (Fly origin) → parent storefront page (shop origin)** | The primary boundary. Every field in `e.data` is attacker-controlled. This handler is the receiver and the only place trust can be enforced — it cannot be enforced in the child. |
| **any third-party window or opener → parent storefront page** | `window.postMessage` is callable by any window with a handle on this one. `Content-Security-Policy: frame-ancestors *` on `/quiz-embed` means any site can also frame the quiz. |
| **the shop page itself → its own listener** | A same-origin script (including a theme app, a tracker, or an injected script) can post to `window` and hit this listener. `e.origin` would be the shop origin, not the app origin. |
| **merchant theme editor → block settings → navigation targets** | `app_url` becomes the trusted origin; the redirect and product settings become navigation targets. |
