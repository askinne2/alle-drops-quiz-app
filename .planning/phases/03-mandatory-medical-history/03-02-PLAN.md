<objective>
Remove the two legacy top-level PHI fields (`personal_history` / `family_history`) from every
application code path, and give both PHI-facing renderers a single shared question-ID → clinical
label map so the new Phase 3 answer keys read correctly for Dr. Sullivan.

Purpose: this is the **application half of D-01's asymmetric migration**. It MUST be deployed and
confirmed live BEFORE the `DROP COLUMN` DDL runs (plan 03-07). `insertSubmission`'s INSERT names its
columns explicitly, so dropping the columns while this code is still live hard-fails EVERY
submission with `column "personal_history_json" of relation "submissions" does not exist`. Read paths
degrade gracefully; the write path does not.

Output: `getAnswerLabel` in `format.ts`, both renderers consuming it, and zero references to the two
legacy fields across `app/`, `tests/`, and `scripts/`.
</objective>
