  present" — those three numbers sum to 9, not 7. The fixture's actual computed total was already 9
  (confirmed by running the suite), so no behavior was wrong, only the comment's arithmetic.
- **Fix:** Corrected the comment to "total = 9" while renaming the bracket label from "7+" to "9+"
  per the plan's own instruction to update that comment.

- **Verification:** `npx vitest run app/lib/quiz/scoring.test.ts` — all 21 tests pass
- **Committed in:** `91cac1a` (part of Task 1's commit)

**2. [Rule 1 - Bug] Two tests would fail post-boundary-move that the plan's action text did not name**
- **Found during:** Task 1 (`app/lib/quiz/score-scale.test.ts`) and Task 2
  (`tests/quiz-results-scale-bar-dom.test.ts`)
- **Issue (a):** `score-scale.test.ts` had a test asserting the zones literally equal
  `[{upTo:2...},{upTo:6...},{upTo:60...}]` (hardcoded, not derived from `SCORE_BRACKETS`). The
  plan's action text for this file only mentioned the *derived* zone-boundary test ("keep the
  `zones[0].upTo === SCORE_BRACKETS.LOW.max` ... assertions unchanged") and did not mention this
  separate hardcoded-literal test, which would fail once the mid zone moved to `upTo: 8`.
  **Issue (b):** `tests/quiz-results-scale-bar-dom.test.ts` had a test ("each bracket's boundary
  score lands in its own zone: 2 -> Low, 6 -> Moderate, 7 -> High") whose case list
  (`{score:7, zone:"High"}`) would fail once score 7 became Moderate instead of High. The plan's
  <behavior> block explicitly specifies the score-8/score-9 boundary behavior this test needed to
  assert, but the file's own action paragraph did not call out this specific test by name.
- **Fix:** Updated the hardcoded zone literal to `[2, 8, 60]` (score-scale.test.ts) and the case
  list to `{score:2,zone:"Low"},{score:8,zone:"Moderate"},{score:9,zone:"High"}`
  (quiz-results-scale-bar-dom.test.ts), matching the plan's own `<behavior>` spec for Task 1.
- **Files modified:** `app/lib/quiz/score-scale.test.ts`, `tests/quiz-results-scale-bar-dom.test.ts`
- **Verification:** Both files pass in the task's `<verify>` command run
- **Committed in:** `91cac1a` (part of Task 1's commit)
