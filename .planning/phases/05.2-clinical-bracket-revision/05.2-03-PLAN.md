  `score_bracket            TEXT NOT NULL CHECK (score_bracket IN ('0-2', '3-6', '7+')),`
This is an INLINE column CHECK, so Postgres auto-named it. The expected name is
`submissions_score_bracket_check`, but the actual name MUST be confirmed against `pg_constraint` at
execution time (plan 05.2-04's job, not this plan's) before the DROP is trusted.

`migrations/004_create_submission_files.sql:99-102` is the precedent for widening a CHECK
additively: `ALTER TABLE ... DROP CONSTRAINT IF EXISTS <name>;` then `ALTER TABLE ... ADD CONSTRAINT
<name> CHECK (col IN (...));`. Follow that shape exactly.

and `submission_access_log` by `postgres`. `ALTER TABLE` requires table ownership, so 005 — which
touches `submissions` only — is executed as `postgres` inside one transaction with
`SET ROLE alledrops_app;` before the ALTERs and `RESET ROLE;` after.
