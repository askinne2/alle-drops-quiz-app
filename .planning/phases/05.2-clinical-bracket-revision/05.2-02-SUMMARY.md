## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `api-admin-submissions.test.ts`'s filter-passthrough test would have gone
inconsistent if only the named literal were swapped**
- **Found during:** Task 3
- **Issue:** The plan's action text instructs swapping every `score_bracket: '7+'` line to `'9+'`.
  `tests/api-admin-submissions.test.ts` has such a line inside an `objectContaining` assertion
  (line 87), but the *input* to that assertion is a URL query string on line 80 —
  `score_bracket=7%2B` (percent-encoded, because a literal `+` in a query string decodes to a
  space under the `application/x-www-form-urlencoded` convention `URLSearchParams` follows).
  Swapping only line 87 to `'9+'` while leaving line 80 as `7%2B` would make the test assert a
  value the code under test never actually produces — the loader would still decode `7+` from the
  URL, and the assertion would fail.
- **Fix:** Changed both together: the URL's `score_bracket=7%2B` to `score_bracket=9%2B`, and the
  expected object's `score_bracket: '7+'` to `'9+'`. This preserves the test's actual purpose
  (verifying percent-decoding of a `+`-containing filter value) with the new label.
- **Files modified:** `tests/api-admin-submissions.test.ts` (already in `files_modified`)
- **Verification:** `npx vitest run tests/api-admin-submissions.test.ts` passes; full suite green
- **Committed in:** `2822cbe` (Task 3 commit)

**2. [Plan ambiguity, resolved by judgment] `tests/pdf.test.ts` acceptance criteria vs. required
regression case**
- **Found during:** Task 3 (read_first)
- **Issue:** Task 3's acceptance criteria state "the five `tests/api-*` files and `tests/pdf.test.ts`
  contain zero occurrences of `score_bracket: '7+'`". The same task's `<action>` and `<behavior>`
  explicitly require adding a new test case in `tests/pdf.test.ts` with `score_bracket: '7+'` as
  the D-52-04 legacy-label regression guard, and require that case be observed failing RED before

- **Resolution:** Followed the more specific instruction — added the legacy-label regression case
  (this plan's own stated central risk: historical rows falling through to a bare label). Read the
  "zero occurrences" bullet as targeting ambient/incidental fixtures (the six one-literal swaps),
  not this deliberately-added, RED-proofed regression case. No code behavior was affected by this
  choice — only which of two acceptance-criteria bullets in the plan text takes precedence.
- **Files modified:** `tests/pdf.test.ts` (already in `files_modified`)
- **Verification:** RED-proof recorded below; full suite green with the case included
- **Committed in:** `2822cbe` (Task 3 commit)
