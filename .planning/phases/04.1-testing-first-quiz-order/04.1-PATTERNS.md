### NEW: bundle relative-position ordering guard test (D-09)

**Analog:** `tests/quiz-bundle-freshness.test.ts` — the whole-file scaffold (imports, `SOURCE`

```typescript
 * [header comment explaining what this test guards against, in this file's established voice]
```

**CRITICAL — occurrence counting rule, non-negotiable (CONTEXT.md D-09 restates this):**
```typescript
const count = (needle: string): number => SOURCE.split(needle).length - 1;
```
Confirmed: this is the ONLY counting mechanism used anywhere in this file. There is no `grep -c`
usage in this repo's test suite — `grep -c` counts matching **lines**, and a minified single-line
bundle collapses any nonzero count to `1`, making `>= 1` assertions vacuous. This has already
burned this project twice per the file's own header comment (:24-27) and CONTEXT.md D-09 repeats
the warning verbatim.

**Pattern for the relative-position assertion itself (new — no exact precedent in this file, since
every existing `it()` here asserts absolute presence/absence, not relative order).** Model it on
the existing `it()` shape but compare two `indexOf` results instead of two `count` results:
```typescript
describe("public/quiz-bundle.js — Part 7 (allergy testing) now precedes Part 1 (symptoms) in flow order (Phase 4.1 reorder, D-09)", () => {
  it("both needles are present at least once (non-vacuity control) before any ordering claim is made", () => {
    // Per D-09: measure both needles nonzero in the SAME fetch/read before claiming anything
    // about their relative order — an absent needle makes indexOf return -1, which would make
    // "testing before symptoms" pass vacuously against a needle that was never there at all.
    expect(count("testing_status")).toBeGreaterThanOrEqual(1);
    expect(count("symptoms_nasal")).toBeGreaterThanOrEqual(1); // or equivalent Part 1 identifier
  });

  it('"testing_status" now appears BEFORE "symptoms_nasal" in the bundle — proves Part 7 precedes Part 1 post-reorder', () => {
    // Pre-4.1 (measured against the committed bundle before this phase): testing_status appears
    // AFTER symptoms_nasal (Part 7 was last). Post-4.1 rebuild: testing_status appears BEFORE
```
