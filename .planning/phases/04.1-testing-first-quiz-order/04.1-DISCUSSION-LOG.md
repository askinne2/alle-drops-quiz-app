**days** (integer) and runs **asynchronously** — up to ~24h latency. `age: 1` means "deleted between
24 and 48 hours." Sub-day windows are not expressible through OLM at all.

## Bundle proof

**Problem surfaced during the wrap-up check, not from the ROADMAP.** Every prior phase proved the
theme bundle was rebuilt by measuring a *new string* 0-before / ≥1-after. A pure array reorder
introduces no new string — every Phase 4 marker already exists in the shipped v51 bundle. ROADMAP
success criterion 5 asks for exactly that measurement and the technique does not apply.

### Q1 — How do we prove the reorder is live?

| Option | Description | Selected |
|--------|-------------|----------|
| Assert relative position in the bundle | Measure `indexOf("testing_status")` vs `indexOf("symptoms_nasal")` in served bytes — a real ordering assertion, plus a guard test so a future reorder can't silently regress. | ✓ |
| SHA-256 committed artifact vs served bytes | Proves freshness and byte-identity; says nothing about order being correct. | |
| Add a deliberate order marker string | Ship a constant naming the 4.1 order so the usual technique still works, at the cost of a string that exists only to be counted. | |

**User's choice:** Assert relative position in the bundle
**Notes:** Became CONTEXT.md D-09, together with the standing occurrence-counting rule
(`split(needle).length - 1`, never `grep -c`) and the cache-buster requirement.
