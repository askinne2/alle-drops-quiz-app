## Decisions Made
- **Test repointing mechanic:** renumbered literals in place rather than deriving indices from `QUIZ_PARTS` at runtime, per the plan's `<test_repointing_decision>` — keeps the three DOM/source-text test files as a loud-failure negative canary against a future accidental reorder, complementing this plan's new positive canary.
- **Corrected a stale assumption in the plan text (Block 2):** the plan's Part 6 exclusion prefix list named `diagnosed_allergic_condition` as a Part 6 id. Reading `questions.ts:241-260` showed it is actually a genuine Part 5 question (`part: 5`, `yesno` type contributing 0 points, positioned adjacent to the Part 5 medication questions per PROJECT.md's DIAG-01 requirement) and legitimately belongs in `ALL_SCORED_QUESTIONS`. Including it in the exclusion set produced a false-positive test failure against correct code (`expected [] to have length 0 but got 1`). Removed it from the exclusion prefix list with an inline comment recording why, verified against source before writing the fix. This is a Rule 1 auto-fix — the test's intent (no genuine Part 6 medical-history id should be scored) is preserved; only the incorrect assumption about which id belongs to which part was corrected.
- **Avoided the literal substring `grep -c` inside the new test file's own header comment**, rephrasing the counting-rule warning to `grep with the count flag` — the plan's own acceptance criterion (`grep -c 'grep -c' tests/quiz-parts-order.test.ts` outputs `0`) would otherwise fail against the file's own prose explaining why `grep -c` is banned. The warning's meaning is preserved; only the exact string is avoided.
