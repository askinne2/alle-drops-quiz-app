## READ THIS BEFORE WRITING THE GUARD — D-09's stated technique does not work, and here is the measurement that proves it

CONTEXT.md D-09 and PATTERNS.md both specify asserting
`SOURCE.indexOf("testing_status") < SOURCE.indexOf("symptoms_nasal")` on the rebuilt bundle.
**That assertion cannot flip, and would fail after a correct rebuild.**

Measured against the committed pre-4.1 bundle on 2026-08-10:

| needle | occurrences | indexOf |
|---|---|---|
| `testing_status` | 7 | 160970 |
| `symptoms_nasal` | 2 | 153560 |

The reason those positions are fixed: string literals live inside the minified `PART*` const
declarations, whose order in the emitted module follows **source declaration order in
`app/lib/quiz/questions.ts`**, not `QUIZ_PARTS` order. The relevant emitted bytes are:

`…ns=[{kind:"question",id:"symptoms_nasal",…}]…us=[{kind:"question",id:"testing_status",…}]…`
`…const Vl=[ns,rs,ls,is,os,ss,us],$l=Vl.flat()…`

Reordering the `QUIZ_PARTS` array literal moves seven one-to-two-character identifier tokens inside
`[...]`. It moves **no string literal**. `indexOf("testing_status")` stays at ~160970 and
`indexOf("symptoms_nasal")` stays at ~153560 after a perfectly correct rebuild — the assertion would
read as a stale bundle when the bundle is in fact right. Choosing a different identifier pair does
not help; no pair works, because nothing about string positions changes.

**Corrected mechanism, which satisfies D-09's purpose exactly (artifact-level order proof,
non-vacuity control, `split(needle).length - 1` counting, RED-before / GREEN-after):** extract the
minified `QUIZ_PARTS` array from the bundle by anchoring on the `.flat()` call that immediately
follows it, resolve each part's minified identifier by looking up the declaration that heads it with
a known question id, and assert positional identity. Prototyped against the current committed bundle
on 2026-08-10 and confirmed working:

- regex `/([A-Za-z_$][\w$]*)=\[((?:[A-Za-z_$][\w$]*,){6}[A-Za-z_$][\w$]*)\],[A-Za-z_$][\w$]*=\1\.flat\(\)/`
  matched exactly once, yielding `Vl=[ns,rs,ls,is,os,ss,us],$l=Vl.flat()`
- regex `/([A-Za-z_$][\w$]*)=\[\{kind:"question",id:"<QID>"/` resolved
  `symptoms_nasal -> ns`, `testing_status -> us`, `history_comorbidities -> ss`
- against the PRE-reorder bundle the extracted order is `[ns, …, ss, us]`, i.e. element 0 is the
  Part 1 identifier and element 6 is the Part 7 identifier — **the assertion below is RED today**,
  which is this phase's before-measurement
- after a correct rebuild the extracted order must be `[us, ns, …, ss]`

Minified identifier names are not stable across builds, so the guard must never hardcode `ns`/`us`
— it re-derives both from the same file read on every run. That makes it robust, not brittle.

**Bundle freshness itself** is proven separately by the byte-size delta plus the two-build
determinism hash, exactly as plans 04-09 and 04-18 did. D-09 correctly rejects inventing a new
string marker; this phase does not add one.
