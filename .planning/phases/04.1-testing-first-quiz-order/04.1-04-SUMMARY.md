## Known Discrepancy: `grep -c 'grep -c'` cannot reach 0 for this file

The plan's Task 2 acceptance criteria state `grep -c 'grep -c' tests/quiz-bundle-freshness.test.ts`
must output `0`. As verified this session, it outputs **5**, not 0 — down from a hypothetical 6 had
the fix above not been applied, but not 0.

**Why this cannot be fixed within this plan's constraints:** all 5 remaining occurrences are inside
block comments that were already committed to this file by earlier plans (04-09, 04-18, and the
Phase 2/3/4 blocks), predating Phase 4.1 entirely. They document the same "never `grep -c`,
use `SOURCE.split(needle).length - 1`" counting rule that this plan's own new block also documents
(now without the literal phrase, per the fix above). This plan's Task 2 explicitly requires "Do not
modify any existing `describe` block, any existing marker, or the shared `count` helper," and the
plan's own append-only verification (`git diff tests/quiz-bundle-freshness.test.ts | grep -c
'^-[^-]'` outputs `0`) forbids touching that prior text. There is no way to simultaneously satisfy
"append-only, don't touch existing blocks" and "zero occurrences of a phrase that already exists 5
times in those existing blocks."

**Practical effect:** none. The intent behind the acceptance criterion — that the file's actual test
logic never invokes the shell command `grep -c` to count occurrences (only `SOURCE.split(needle)
.length - 1` is used anywhere in the file, confirmed: `grep -c 'split('` = 6, one call site per
`describe` block including this plan's new one) — is fully satisfied. The 5 remaining matches are
English-language warnings against using `grep -c`, not invocations of it. This same criterion was
almost certainly already unsatisfiable before this plan touched the file (04-18's block alone
contributes 2 of the 5), meaning it was written without accounting for the file's own established
documentation convention repeating the warning in every new block. Flagging here rather than
silently working around it or violating the append-only constraint to force a `0`.
